# 阶段 5：g-helper 数据桥接（路线 A）· 使用说明

> 目标：不再依赖 AIDA64（免费版 30 天试用）读 CPU 温度/功耗，改用与 **g-helper 同源**的数据通道：
> 华硕 EC 直读（ATKACPI）+ Intel RAPL 能量计 + nvidia-smi，并新增**性能模式**和**风扇转速**显示。

---

## 一、文件夹内容

| 文件 | 作用 |
|---|---|
| `05_ghelper_bridge.py` | 电脑端数据服务（管理员运行，端口 8080） |
| `04_widget_ghelper/04_widget_ghelper.ino` | ESP32 副屏固件（在 04_widget 基础上加模式/风扇行） |
| `使用说明.md` | 本文档 |

## 二、快速上手（2 步）

### 第 1 步：电脑端跑服务

1. 安装依赖（命令行执行一次即可）：
   ```
   pip install psutil pywin32
   ```
2. 先**停止旧的 `03_pc_server.py`**（共用 8080 端口）。
3. 右键以**管理员身份**运行（ATKACPI 必须提权）：
   ```
   python 05_ghelper_bridge.py
   ```
   首次会弹 UAC 确认，同意即可。若直接双击失败，也可在 cmd 里手动执行上面的命令。
4. 验证：浏览器打开 `http://127.0.0.1:8080`，应看到类似：
   ```json
   {"cpu":12,"mem":64,"cpu_temp":58,"cpu_pwr":45.3,"gpu_temp":58,"gpu_pwr":7.9,
    "gpu_usage":6,"time":"21:05:33","mode":1,"mode_name":"TURBO","fan_cpu":2800,"fan_gpu":3200}
   ```

> 想只看传感器是否都读得到，先运行：`python 05_ghelper_bridge.py --test`

### 第 2 步：烧录副屏固件

1. Arduino IDE 打开 `04_widget_ghelper/04_widget_ghelper.ino`。
2. 把 `==== 改成你的 ====` 之间的 WiFi 名、密码、电脑 IP 改成你的（与 04_widget 相同位置）。
3. 选择 `ESP32 Dev Module` + 对应 COM 口，上传。

## 三、数据来源（每个字段读自哪里）

| 字段 | 主来源 | 兜底 |
|---|---|---|
| `cpu` / `mem` | psutil | - |
| `cpu_temp` | 华硕 EC 直读（ATKACPI `0x00120094`） | AIDA64 注册表 |
| `cpu_pwr` | Windows 性能计数器 `Energy Meter\Power`（Intel RAPL） | AIDA64 注册表 |
| `gpu_temp/gpu_pwr/gpu_usage` | `nvidia-smi` | AIDA64 注册表 |
| `mode` / `mode_name` | 华硕 EC 直读（ATKACPI `0x00120075`） | g-helper 注册表 `HKCU\Software\GHelper\performance_mode` |
| `fan_cpu` / `fan_gpu` | 华硕 EC 直读（ATKACPI `0x00110013/14`），EC 返回 RPM÷100，脚本按 `FAN_SCALE=100` 换算 | 读不到显示 `--` |
| `battery_w` | 华硕 EC 直读（电池放电功率） | 插电充电时为 `null`（正常，只有用电池时才放电） |

模式对应关系：`0=平衡 BALANCED（绿）` `1=增强 TURBO（红）` `2=静音 SILENT（青）` `3=全速 FULL（橙）` `4=手动 MANUAL（黄）`。

## 四、常见问题

| 现象 | 原因与解决 |
|---|---|
| 提示"打开 \\.\ATKACPI 失败" | 没用管理员身份运行；右键"以管理员身份运行" |
| 提示"端口 8080 被占用" | `03_pc_server.py` 还开着，先停掉它 |
| `cpu_pwr` 一直是 null / 0 | `Energy Meter` 计数器不可用（未装 pywin32 或芯片组驱动未提供）。装好 pywin32 后重启脚本；仍不行会自动回退 AIDA64 |
| 模式显示 `----` | g-helper 的 EC 寄存器只写不读 且 g-helper 没运行过（注册表无记录）。运行一次 g-helper 切一次模式即可，或改用 Armoury Crate 切换 |
| 风扇数值不对（如显示 3000 但实际 3000 的倍率差） | EC 返回 RPM÷100，脚本已按 `FAN_SCALE=100` 换算。若与 Armoury Crate 显示不一致，改脚本顶部 `FAN_SCALE` 系数 |
| GPU 三个字段全是 null | `nvidia-smi` 不在 PATH，或显卡驱动未装 NVIDIA 驱动 |
| `battery_w` 是 null | 正常。只有用电池放电时才返回数值，插电充电时为 null |
| 温度/功耗数值和 AIDA64 略有差异 | 正常。EC 温度≈CPU Package；功耗 RAPL 读的是整个 package 能量计，更接近真实 |

## 五、为什么这样做（对比旧方案）

- **摆脱 AIDA64 试用限制**：AIDA64 免费版 30 天后只能看有限传感器；ATKACPI/RAPL/nvidia-smi 全部免费且原生。
- **更准的 GPU 数据**：nvidia-smi 直接读驱动，不再靠正则猜 AIDA64 的字段名。
- **新增内容**：性能模式（平衡/增强/静音/全速/手动）+ CPU/GPU 风扇转速 + 电池放电功率。
- **保留兼容**：如果哪天想切回 `03_pc_server.py`，旧固件 04_widget 依然能用；新固件读旧服务时模式/风扇显示 `--`，其余正常。
